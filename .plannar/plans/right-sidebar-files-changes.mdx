# Right sidebar — Files & Changes

Add a **secondary sidebar on the right edge** of the workspace, mirroring the existing
left `ProjectSidebar`. A thin strip with a collapse icon, plus two subtabs: **Files**
(a VS Code–style lazy file tree that creates files/folders and opens them as editor
tabs) and **Changes** (committed/unstaged git lists that open read-only diff tabs).

Files open in the **main tab bar** as two new tab kinds — `editor` (CodeMirror 6, save
on ⌘/Ctrl-S, no autosave) and `diff` (read-only `@codemirror/merge`). Filesystem and
git work lives in Rust behind worktree-scoped Tauri commands; the frontend never sees an
absolute path.

- **Security boundary:** every fs/git command takes a `worktreeId` + a **worktree-relative** path; Rust resolves + canonicalizes against the worktree root and rejects traversal — no absolute paths cross IPC

## Resolved decisions

The four questions that shaped this design, and what we settled on.

    <TableRow>

<Accordion type="single" collapsible className="my-4">
  <AccordionItem value="locator">
    <AccordionTrigger>Why explicit fields over reusing `url`?</AccordionTrigger>
    <AccordionContent>

`url` is documented in the schema as _"the current page URL for browser tabs"_. A diff
tab needs **two** pieces of data (path + which side), which a single string can't hold
without an opaque `"unstaged:src/app.ts"` encoding. That overloaded-field ambiguity is
exactly what the repo's _"one source of truth / clean architecture"_ rule warns against.

- **Chosen:** add `filePath: string | null` and `diffSide: DiffSide | null` to `Tab`; keep `url` browser-only. Cost: a `v5` `ALTER TABLE tabs ADD COLUMN file_path TEXT; ADD COLUMN diff_side TEXT;` (the same gated pattern as v2/v3/v4) and two fields on the Rust `Tab` struct.
- **Rejected alternative:** reuse `url` as a generic locator (no migration). Cheaper, but couples three unrelated tab kinds to one stringly-typed column and forces every consumer to parse it.

The migration is cheap and well-trodden here; clarity wins.

</AccordionContent>
  </AccordionItem>
  <AccordionItem value="relative">
    <AccordionTrigger>Why worktree-relative paths everywhere?</AccordionTrigger>
    <AccordionContent>

Every fs/git command takes a `worktreeId` and a path **relative to the worktree root**.
The backend looks up the trusted absolute root from the DB (`worktrees.path`) and
resolves the relative path against it, canonicalizing and rejecting any `..` / absolute /
symlink escape. This keeps the IPC surface incapable of reading or writing outside the
worktree, and means a persisted `filePath` round-trips cleanly even if the worktree is
later moved on disk.

</AccordionContent>
  </AccordionItem>
</Accordion>

  <CardHeader>
    <CardTitle>Path-safety core</CardTitle>
  </CardHeader>
  <CardContent className="text-sm">

`resolve_in_worktree(root, relative)` rejects absolute paths and `..` components
_before_ touching disk, then canonicalizes the target (or its deepest existing ancestor,
for create/exists) and asserts `starts_with(canonical_root)` to defeat symlink escapes.
Traversal/absolute → `InvalidInput`; IO failures → `Io`; git non-zero → `Git(stderr)`.

</CardContent>

<Accordion type="single" collapsible className="mt-3">
  <AccordionItem value="git">
    <AccordionTrigger>Exact git invocations (status, diff, base)</AccordionTrigger>
    <AccordionContent>

All run as `git -C <worktree> …` with `-z` (NUL-terminated) for robust parsing.

- **Base / merge-base:** DB lookup of the worktree's `parent_id` → parent's `branch` = `base_ref`; then `git merge-base HEAD <base_ref>` → fork-point SHA (diff against the fork point, not the parent's moved tip). Parentless/main worktree or unrelated histories → no base; the **Committed** group is empty and the UI says so.
- **Committed list:** `git diff --name-status -z --find-renames <merge_base> HEAD` — everything B has committed since it forked from base A. (No-HEAD repos → empty.)
- **Unstaged list:** `git diff --name-status -z --find-renames` (working tree vs index — i.e. what is _not staged_) **plus** `git ls-files --others --exclude-standard -z` for untracked.
- **Committed diff:** old = `git show <merge_base>:<path>` (empty if added in B), new = `git show HEAD:<path>` (empty if deleted in B).
- **Unstaged diff:** old = `git show :<path>` (the index/staged version; empty for untracked), new = working-tree file via `fs::read_file` (empty if deleted on disk).
- **Binary:** `git diff --numstat -z` reporting `-`/`-` → `binary: true`, empty texts (never push bytes through IPC). Renames carried via `oldPath`.

</AccordionContent>
  </AccordionItem>
  <AccordionItem value="filecontents">
    <AccordionTrigger>read_file: binary & large files</AccordionTrigger>
    <AccordionContent>

`byteSize` from metadata. Over a 2 MiB cap → `truncated: true`, no read. Else read bytes
and try `String::from_utf8`; on failure → `binary: true`, empty text. The editor renders a
"binary / too large" placeholder instead of garbage; `write_file` overwrites in place and
does not create missing parents.

</AccordionContent>

  <AccordionItem value="tests">
    <AccordionTrigger>cargo tests (deterministic, temp git repo)</AccordionTrigger>
    <AccordionContent>

Each test `tempfile::tempdir` + `git init` + commits, mirroring existing `git.rs` tests.

## Three flows, end to end

<Accordion type="single" collapsible className="my-4">
  <AccordionItem value="create">
    <AccordionTrigger>Create a file from the tree</AccordionTrigger>
    <AccordionContent>

1. User clicks **New File** → `FilesTab` sets `createMode = { dirPath: selectedDir, kind: "file" }` and ensures `selectedDir` is expanded.
2. `FileTreeNode` for `selectedDir` renders `NewEntryInput` as its first child; input autofocuses.
3. On each keystroke, validate against the loaded siblings (case-insensitive) + reject empty / path separators; red border while invalid.
4. **Enter** → `createFile(worktreeId, joinPath(dirPath, name))`. Backend `File::create_new` fails atomically if it exists (UX validation is a convenience, backend is the guard).
5. On success → clear create mode, re-`listDirEntries(dirPath)` to refresh, then `openFileTab(joinPath(dirPath, name))` → opens an `editor` tab in the main bar. (Folders: same, minus the open.)

</AccordionContent>
  </AccordionItem>
  <AccordionItem value="edit">
    <AccordionTrigger>Open & save an editor tab</AccordionTrigger>
    <AccordionContent>

1. Double-click a file (or open-on-create) → `openFileTab(path)` dedupes by `kind`+`filePath`; if found, activate it, else `createTab(projectId, worktreeId, "editor", basename(path), …, filePath)` + `add-tab`.
2. `SplitPane` routes `kind === "editor"` → `<EditorView>`, keyed on `tab.id`.
3. `EditorView` `readFile(worktreeId, filePath)` → initial doc; binary/large → placeholder; missing → inline error + Retry.
4. Typing fires `onChange` → `setTabDirty(tab.id, doc !== savedDoc)`; the strip shows a dot instead of ✕.
5. ⌘/Ctrl-S → `writeFile` → clear dirty + new baseline + toast. Closing a dirty tab routes through `confirmAndCloseTab` (Save / Don't save / Cancel).

</AccordionContent>
  </AccordionItem>
  <AccordionItem value="diff">
    <AccordionTrigger>View a change as a diff</AccordionTrigger>
    <AccordionContent>

1. `ChangesTab` calls `worktreeChanges(worktreeId)` → two lists; group each by `dirname(path)` with a relative path label.
2. Click a row → `openDiffTab(path, side)` (dedupe by `kind`+`filePath`+`diffSide`).
3. `SplitPane` routes `kind === "diff"` → `<DiffView>`.
4. `DiffView` `fileDiff(worktreeId, path, side, oldPath?)` → `{ oldText, newText, binary }`; renders read-only `MergeView`. Committed → base-branch fork point vs `HEAD`; unstaged → index vs working tree. Recomputed live on reopen (nothing diff-related persisted).

</AccordionContent>
  </AccordionItem>

## Risks & edge cases

<Card className="my-4">
  <CardContent className="text-sm space-y-2 pt-6">

- **Base branch unresolvable** (main/parentless worktree, detached HEAD, unrelated histories) → the **Committed** group is empty and labeled "No base branch"; the Unstaged group still works (it doesn't need a base).
- **File both committed and re-edited** → appears in **both** groups: Committed shows the committed delta vs base A, Unstaged shows the further uncommitted edit. These are different axes, so this overlap is intentional, not a bug.
- **Two tabs for one file** → `openFileTab`/`openDiffTab` dedupe before creating.
- **Dirty close / file deleted on disk** → `confirmAndCloseTab` dialog; save errors toast and stay dirty; missing-file tab shows inline error rather than crashing workspace load.
- **Binary / large files** → backend flags; editor & diff render placeholders, never raw bytes over IPC.
- **CRLF / autocrlf** → `git show` may normalize EOL vs raw working-tree read; EOL-only diffs possible (cosmetic) — flagged.
- **Tree context menu over a browser pane** → wrap the `context-menu`'s open state with native-overlay suppression (`native-overlay.ts`), like other floating UI.
- **CodeMirror in jsdom** → mock `@uiw/react-codemirror`; never mount real `MergeView` in unit tests.
- **gitignore spawn cost** → one batched `git check-ignore --stdin -z` per directory expansion (not per entry).

</CardContent>
</Card>
