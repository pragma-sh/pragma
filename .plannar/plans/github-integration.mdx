# GitHub Integration

A comprehensive GitHub integration for Pragma: **authorization** (OAuth or `gh` CLI),
a **full-screen setup modal**, and a third **Pull Request** subtab in the right sidebar
that creates, views, and reviews PRs. GitHub API calls use the **Octokit SDK**; secrets,
git, and OS work stay in Rust behind typed Tauri commands.

- **New backend deps:** `keyring` (OS keychain token store), `reqwest` (`rustls-tls`, device-flow HTTP)
- **New Rust module:** `src-tauri/src/github.rs` — auth, device flow, `gh` detection, repo-ref + fetch/ahead-behind + push + remote-branch delete (11 commands)
- **New frontend service:** `src/lib/github.ts` — the **single** Octokit entry point (mirrors the `lib/tauri.ts` "only place `invoke()` is called" rule)

- **New shadcn:** `dialog`, `checkbox`, `avatar` (added to `apps/pragma`); plan-render set already has what it needs

## Architecture decisions

<Tabs defaultValue="octokit" className="w-full">
  <TabsList>
    <TabsTrigger value="octokit">Octokit placement</TabsTrigger>
    <TabsTrigger value="oauth">OAuth flow</TabsTrigger>
    <TabsTrigger value="diffs">Review data source</TabsTrigger>
  </TabsList>

<TabsContent value="octokit">

The repo rule is "all backend calls go through `lib/tauri.ts`," but Octokit is a
**JS-only SDK** and the user requires it. We honor both:

- **GitHub REST/GraphQL → Octokit in one module** `src/lib/github.ts`, the single place
  `new Octokit()` happens — the same discipline as the `invoke()` rule. Components call
  typed helpers, never construct a client.
- **Secrets, OS, git → Rust.** Token storage, device-flow polling, `gh` detection,
  `git fetch`/ahead-behind/push, browser-open. The token lives in the **OS keychain**
  (never plaintext SQLite); the frontend pulls it via `github_token` to build the client.

</TabsContent>

<TabsContent value="oauth">

Use the **OAuth Device Flow** as the recommended path:

- **No client secret** — mandatory for a distributed desktop app (an embedded secret
  can't stay secret; GitHub doesn't support PKCE for OAuth apps).
- Matches "open the browser to the login flow": request a device code, open
  `https://github.com/login/device` (showing the `user_code`), poll for the token.
- Driven from Rust so the secret-free `client_id`/scopes come from `@pragma/constants`
  and the token lands in the keychain without round-tripping through JS.

`gh` CLI path: detect with `gh auth status`; read token via `gh auth token`. The CLI
button is **hidden** unless `gh` is authenticated.

</TabsContent>

<TabsContent value="diffs">

- **File list + patches** → Octokit `pulls.listFiles`.
- **Side-by-side review diffs** → produced **locally** (`git diff` of `base...HEAD` per
  file) so the existing `@codemirror/merge` `DiffView` gets real before/after text.
- **Review comments + resolved state** → Octokit. **Resolving a thread needs GraphQL**
  (`resolveReviewThread`) — REST can't resolve; Octokit's `.graphql()` covers it.

</TabsContent>
</Tabs>

## The Pull Request subtab

Add `"pullRequest"` to `RightSidebarSubtab` (`state/right-sidebar-context.tsx`, plus the
`SUBTAB_KEY` parse) and a third `TabsTrigger` in `RightSidebar.tsx`. The controller
`components/right-sidebar/PullRequestTab.tsx` resolves state and polls like `ChangesTab`.

<TabsContent value="create">

`components/github/CreatePullRequestView.tsx` — top→bottom: shadcn `Input` title
(defaulted to last commit subject), TipTap markdown editor, then `Create pull request`
(primary) + `Create draft`.

**Pre-flight on submit** (`github_fetch_and_sync` first):

- `behind > 0` → **block** with an error `AlertDialog` (pull/rebase first).
- staged/unstaged uncommitted changes → **warn, not block**: confirm `AlertDialog`
  ("changes won't be part of this PR — create anyway?").
- if `!hasUpstream` → `github_push_branch`, then `createPullRequest`. On success the
  controller re-resolves into the **view** state.

`components/github/MarkdownEditor.tsx` — TipTap `StarterKit` (its plain code block
disabled) + `CodeBlockLowlight` + `Link` + `Placeholder` + the `tiptap-markdown`
extension. Seed with `setContent(markdown)`; read with
`editor.storage.markdown.getMarkdown()` so **I/O is markdown**.

</TabsContent>

<TabsContent value="view">

`components/github/ViewPullRequestView.tsx`, sections top→bottom:

1. **Header card** — title, `#number` with **open-in-browser** link (`html_url`), state
   badge, `base ← head` chips, body rendered as markdown (`react-markdown` + `remark-gfm`).
2. **Conversation** — `listIssueComments`, **read-only** (excludes review comments).
3. **Files changed** — reuse **`ChangeGroup`** (same formatting as Changes) fed by
   `listPullFiles`; `onOpen` → `openReviewTab(prNumber, path)`; per-file unresolved-comment badge.
4. **Merge card** — `getChecksStatus` summary line + **Merge** button. Confirm dialog →
   `mergePullRequest` → **branch-cleanup dialog**: a `Checkbox` for "also delete the
   remote branch", reuse `deleteWorktree(deleteBranch: true)` for worktree + local branch,
   `github_delete_remote_branch` for the remote.

</TabsContent>

<TabsContent value="review">

New `TabKind: "pr-review"` (constants enum + `v7` `pr_number` column; `createTab`/`list_tabs`
carry it; `openReviewTab` on the workspace context dedupes by kind+prNumber; `SplitHost`
renders it).

`components/github/ReviewTab.tsx` — a scrollable list of files. Each file:

- Sticky header + a **"Done reviewing" checkmark** (ephemeral module store keyed by
  `prNumber:path`, like `editor-dirty-store.ts`; collapses the diff when checked).
- **Side-by-side diff** via the existing `@codemirror/merge` `DiffView`, fed by
  `github_pr_file_diff`.
- **Inline review comments** anchored to the file — compact card with the body +
  a **Resolve** button (`resolveReviewThread`); resolved threads dim/collapse.

</TabsContent>
</Tabs>
