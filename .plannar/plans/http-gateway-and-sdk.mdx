# HTTP gateway + `@pragma/sdk` rewrite

A new Rust crate, `crates/pragma-gateway`, fronts `pragma-server`'s Unix-socket RPC surface
with a localhost HTTP/JSON API, and `@pragma/sdk` is rewritten from a `node:child_process`
wrapper around `pragma-cli` into a portable `fetch`-based client for that API. There are
**two connections** end to end: SDK → gateway is HTTP (connection 1); gateway → `pragma-server`
is the existing Unix socket (connection 2), unchanged. The gateway carries zero business
logic and zero frontend dependency — it only translates HTTP to the wire protocol that
already exists.

- **New crate `crates/pragma-gateway`** — binary, depends only on `pragma-protocol`,
  `pragma-client` (feature-limited), `@pragma/constants`'s Rust side. Never depends on
  `pragma-core` or anything under `apps/pragma`.
- **Router: `tiny_http`**, already in the lockfile and used by `dev_bridge.rs` — see the
  comparison below.
- **Route scheme:** `POST /v1/rpc/{method}` passthrough for the 11 `ProtocolRpcMethod`
  wire methods, plus dedicated routes for sessions/agents/subscriptions (stateful,
  streaming, or binary — don't fit the generic RPC envelope).
- **Streaming:** NDJSON over `fetch` + `ReadableStream` everywhere (sessions, agent
  events, subscriptions) — no SSE, no WebSocket.
- **Discovery:** ephemeral port + `gateway.json` (`{port, token, pid, protocolVersion}`,
  mode `0600`) beside `daemon.sock`. The SDK reads `PRAGMA_GATEWAY_URL` /
  `PRAGMA_GATEWAY_TOKEN` env vars (or explicit constructor config) — it cannot read files.
- **SDK rewrite shape:** one `PragmaClient` class with namespaced groups
  (`fs`/`git`/`exec`/`sessions`/`agents`/`events`), plus a low-level `rpc()` escape hatch.
  Portable to any `fetch`-capable JS runtime.
- **Agent reporting rewrite:** `reportStarted`/`reportStopped`/`reportAttention`/
  `reportCleared` stay as top-level functions but return `Promise<void>` and gain an
  SDK-side no-op guard outside a Pragma session.
- **Untouched:** `pragma-server` (invariants, no TCP/auth added to it directly),
  `pragma-cli`, `claude-code-plugin`, `cursor-plugin` (still shell to `pragma-cli` →
  socket directly).

- **`panic = "abort"`** is set workspace-wide (`Cargo.toml`, inherited by
  `pragma-gateway`). One panicking thread aborts the whole process regardless of
  sync or async — `axum`'s per-task panic isolation buys nothing here.

  that model keeps the gateway's mental model identical to the thing it's fronting.

### Streaming, auth, and discovery

- **Streaming mechanics:** each streaming HTTP request thread opens its own dedicated `UnixStream` via `pragma-client` (`attach_stream`/`subscribe_stream`), one Unix connection per HTTP stream — mirrors `pragma-server`'s one `forward_events` loop per connection. Frames are re-serialized one JSON line per event (`{'{'}"type":"output","dataBase64":...{'}'}`, `title`, `exit`) through a `tiny_http` chunked response backed by a custom `Read` over an `mpsc::Receiver<Vec<u8>>`. The stream ends on an exit event or client disconnect (write failure/timeout, same discipline as `pragma-server`'s `CLIENT_WRITE_TIMEOUT`).
- **PTY input exception:** `POST /v1/sessions/{'{'}id{'}'}/input` carries raw bytes (`application/octet-stream`), not base64-JSON — a deliberate exception to the JSON style for the hot path, matching `pragma-client/AGENTS.md`'s "no per-keystroke JSON requests" rule. The gateway forwards the body straight into `PragmaClient::write(session_id, data)`, which already coalesces via its fire-and-forget writer thread.
- **Auth + discovery:** bind `127.0.0.1` only, hard error on any non-loopback bind request. On startup: generate/accept a ≥32-char token, write `<app-data-dir>/<channel>/gateway.json` (`{'{'}port,token,pid,protocolVersion{'}'}`, mode `0600`) before accepting connections. Stale-file detection mirrors `pragma-server`'s `remove_stale_files`: probe the recorded pid/port via `GET /v1/health`; stale → delete and proceed, live → refuse.
- **Constants additions:** a new `gateway` section in `packages/constants` (schema + values) mirroring `daemon` — `gateway.discoveryFile = "gateway.json"`, optionally `gateway.tokenHeader`. Deliberately **no port constant** — the port is runtime-assigned.

## SDK: `@pragma/sdk`

### Public API shape

One `PragmaClient` class holds resolved config (base URL, token, `fetch` impl); flat
functions don't scale to ~30 ops plus streaming.

```ts
const client = new PragmaClient({ baseUrl, token }); // or env-resolved

await client.fs.readFile({ root, path });
await client.git.stageFile({ root, path });
await client.exec.run({ cwd, commands });
const { sessionId } = await client.sessions.spawn({ cwd, cols, rows });
await client.agents.markAgentsSeen({ tabId });
await client.rpc("kanban", { op: "..." }); // low-level escape hatch, unsupportedMethod today
```

### Type sourcing

- **Reuse, don't redefine:** everything already in `@pragma/constants`
  (`ProtocolRpcMethod`, `ProtocolEventKind`, `ProtocolErrorCode`, `AgentReportPayload`,
  `DirEntry`, `FileContents`, `WorktreeChanges`, `FileDiff`, `BranchSyncStatus`, etc.)
  is imported, not hand-copied.
- **Hand-write with a codegen TODO** the shapes that only exist as internal Rust
  structs today: `MergedStatusItem`, `GithubRepoInfo` (git.rs's ad-hoc shape —{" "}
  <strong>not</strong> the same as constants' `GitHubRepoRef`, do not conflate),
`ExecRequest`/`CommandResult`, per-op `Fs`/`GitRequest` input shapes,
`SpawnOptions`/`SessionHandle`/`SessionEvent`, generic `SubscriptionEvent<T>`. Live
in `packages/sdk/src/types/*.ts`, one file per domain.

### Transport, errors, streaming

- `PragmaClientConfig { baseUrl?, token?, fetch?, headers? }`. Resolution order:
  constructor option → `readEnv("PRAGMA_GATEWAY_URL"/"PRAGMA_GATEWAY_TOKEN")` → error —
  there is no default port to fall back to, since it's ephemeral by design.
- `src/env.ts`: `readEnv(name)` is the **only** place `process.env` is touched — guarded
  `globalThis.process?.env?.[name]`, returns `undefined` in browsers/workers, so nothing
  else needs a runtime check.
- `fetchImpl` defaults to `globalThis.fetch` (Node ≥18, Bun, Deno, browsers, workers),
  constructor-injectable for trivial testing without `vi.stubGlobal`.
- Errors: `PragmaGatewayError extends Error { code: ProtocolErrorCode; httpStatus; cause? }`
  for non-2xx / error envelopes; `PragmaTransportError extends Error` for network-level
  failures (fetch throw, non-JSON body). `instanceof` narrowing, per repo convention.
  `PragmaCliError` is deleted.
- Route strings live in `src/routes.ts` — the single point of coupling to the gateway's
  route table above; a route change is a one-file SDK diff.

```ts
for await (const ev of client.sessions.attach(sessionId, { signal })) {
  if (ev.type === "output") renderBytes(base64ToBytes(ev.dataBase64));
}
```

- NDJSON parsing: `Response.body` + `TextDecoder`, manual chunk decode + line splitter
  (not `TextDecoderStream`, for portability), exposed as async generators. Cancellation
  is the caller's `AbortSignal` passed to `fetch`; a generator `finally` cancels the
  reader so `break` from `for await` cleans up.
- Binary PTY output arrives as `{'{'}"type":"output","dataBase64":...{'}'}`;
  `src/encoding.ts` provides dependency-free `base64ToBytes`/`bytesToBase64` via
  `atob`/`btoa` with a manual-table fallback — no `Buffer`, no
  `Uint8Array.fromBase64` (too new to rely on).
- `sessions.write(sessionId, bytes)` POSTs a raw octet-stream body and resolves once
  sent — fire-and-forget, matching the gateway's input hot path.

### Agent reporting rewrite

<Badge variant="outline">breaking change</Badge> for `opencode-plugin`, the sole consumer (verified
by repo-wide grep) — authorized, low risk since it never reads the result.

- New options: `{'{'}agent, worktreeId?, kind?, client?, env?, signal?{'}'}`.
  the old agent spawn options (`executable`/`cwd`) are retired — meaningless over HTTP.
  `AttentionKind` becomes an alias/re-export of constants' `AgentAttentionKind`.
- Each function builds an `AgentReportPayload` (status mapping
  started→running, stopped→done, attention→attention, cleared→cleared), reads
  `PRAGMA_TAB_ID`/`PRAGMA_WORKTREE_ID` via `readEnv` (or an `env` override so
  `opencode-plugin` keeps its merged-env capability), and POSTs via
  `client.agents.report` on a lazily-created default client.
- **SDK-side no-op guard:** each `reportX` checks `hasPragmaEnvironment()` first and
  resolves without any network call outside a Pragma session — the guard moves from
  the plugin into the SDK, matching the root `AGENTS.md` intent that plugins stay thin.
- Return type: `Promise<void>` (was a CLI result object).
- `claude-code-plugin`/`cursor-plugin` are untouched — they still shell to `pragma-cli`
  → socket. `packages/sdk/AGENTS.md` gets a forward-looking note that `pragma-cli`
  could later target the gateway too; `crates/pragma-cli` itself is not touched by
  this plan.

### Bundling, portability, file layout, testing

- `bunup`'s `Target` is `"bun" | "node" | "browser"` — no `"neutral"` — so `--target
node` stays for CJS output. Portability comes from zero `node:`/Bun APIs in `src/`,
  verified by a post-rewrite grep for `node:` imports. `exports` map, `files:
["dist"]`, ESM+CJS+`.d.ts` outputs, and zero runtime dependencies are all unchanged.
- Drop `"types": ["node"]` from `packages/sdk/tsconfig.json` —
  `tsconfig.base.json`'s `lib` (ES2023 + DOM + DOM.Iterable) already provides
  `fetch`/`Response`/`ReadableStream`/`TextDecoder`/`AbortSignal`/`atob`/`btoa` types.
  `@types/node` stays a devDependency for test files' explicit `node:` imports.
- `isolatedDeclarations` (already on) needs explicit return types everywhere, including
  async generators (`AsyncGenerator<EventT, void, unknown>`); verify TS's checker is
  comfortable with that early — fall back to a named iterable class if not.

## Risks & open questions

<Card className="my-4">
  <CardHeader>
    <CardTitle>Risks & open questions</CardTitle>
    <CardDescription>Merged from both design docs</CardDescription>
  </CardHeader>
  <CardContent className="text-sm space-y-2">

- **`ResponseFrame` has no typed error code** — session/agent route errors are
  best-effort classified until a protocol extension adds one (see the Alert above).
- **`pragma-client` feature split touches the desktop app's only transport
  dependency** — needs both a `--no-default-features` build and a full desktop build
  verification; it's a load-bearing crate.
- **Streaming backpressure:** a stalled HTTP client must not pin a gateway
  thread/Unix connection indefinitely — needs a bounded write timeout on chunked
  responses, `CLIENT_WRITE_TIMEOUT`-equivalent.
- **Who supervises `pragma-gateway` in production?** v1 is manual/CLI
  (`pragma-gateway` directly, or a `pragma-cli gateway start` subcommand). An
  app-managed sidecar is a later extension, explicitly out of v1 scope.
- **Env-var injection for the SDK's discovery channel** — `PRAGMA_GATEWAY_URL`/
  `PRAGMA_GATEWAY_TOKEN` need a spawn-time injector. The app's own tab-spawn path
  (wherever `PRAGMA_TAB_ID` is set today) is the likely answer, but the exact
  process/file is unconfirmed and needs owner sign-off before Phase 3 step 2 starts.
- **`GithubRepoInfo` (git.rs) vs `GitHubRepoRef` (constants) shape collision** — verify
  during Phase 2 step 4, don't silently reuse one for the other.
- **Hand-rolled base64** (no `Uint8Array.fromBase64` assumption) — small and testable,
  but a one-time implementation risk worth flagging.
- **`isolatedDeclarations` + async generators under the current TS version** — verify
  early in Phase 2 step 1–3; fall back to a named iterable class if the checker
  struggles.

</CardContent>
</Card>
