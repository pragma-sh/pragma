### SKILL.md frontmatter

```yaml
---
name: agent-plugin
description: Use when building or modifying a Pragma agent plugin — an
  integration that makes a host TUI coding agent (opencode, Claude Code,
  Cursor, or a new tool) report status into Pragma and appear in the
  launcher. Covers the hooks-vs-TypeScript decision tree, @pragma/sdk and
  pragma-cli reporting, defineAgent/createTuiWatcher/defineUsageLimitProvider,
  registration, bundling, and pragma-cli agent verify.
---
```

### Section outline

1. **Intro & scope** — agent plugins only (agents / watchers / usage-limits); explicitly _not_ sidebar tabs, cards, webviews, commands, keybindings, css. Pointers to `CREATE_PLUGIN.md`, `SDK.md`, `CLI.md`.
2. **Decision tree** (opens the working content):
   - Supports TypeScript/JS in-process plugins? Yes → **SDK route** (`@pragma/sdk`, model: `packages/opencode-plugin`).
   - No TS plugins but has a hooks API? → **CLI route** (POSIX `sh` hook script shelling to `pragma-cli agent report`, models: `packages/claude-code-plugin`, `packages/cursor-plugin`).
   - No hooks _and_ no plugin API? → **Watcher route**: a `createTuiWatcher` in the pragma-plugin observes the PTY output stream (`ctx.output`), derives status by parsing the TUI's rendered output (busy spinners, prompt markers, question/approval UI), reports via the watcher's SDK context, and drives approvals/answers with `sendKeys` (`handleDecisions: true`). Least robust — document the parsing-fragility tradeoff.
   - TUI has a default AI provider with account usage? Yes → also add `defineUsageLimitProvider`.
3. **The four reports** — `started`/`stopped`/`attention`/`cleared` semantics, the two iron rules (`stopped` only after `started`; abort/crash → `cleared`, never `stopped`), env guard (`PRAGMA_SERVER_SOCKET` check, silent no-op outside Pragma), never disrupt the host (swallow reporting errors).
4. **SDK route** — reporter construction from `packages/opencode-plugin/src/index.ts:49`, the two-flag `busy`/`attention` state machine from `src/hooks.ts:275`, child-session tracking, `MessageAbortedError` → clear, `reportMessage` streaming with stable ids, requestId round-trips.
5. **CLI route** — hook manifest mapping, `report.sh` patterns from `packages/claude-code-plugin/hooks/report.sh`: per-tab markers, detached transcript watcher for hosts with no cancel hook, blocking `PermissionRequest` → `attention --kind command --request-id` → `await-decision` → verdict JSON; questions via `await-answer --dismiss-output`. Cursor deltas: hook fragments + `install-local.sh`, `startupInput`.
6. **Exact CLI contract** — condensed table; full version in `references/cli-reference.md`.
7. **Pragma-plugin side** — `defineAgent` full field reference (`packages/plugin/src/agent.ts:49`: id must equal the `--agent` id, `launch.command`, models static/async, `args` builders, `startupInput`, `prefill*`), `definePlugin` agent-relevant fields only, `createTuiWatcher` (`handleDecisions: true` when no decision-returning hook exists — opencode; `false` when a blocking hook exists — claude-code/cursor), `defineUsageLimitProvider` shape and both real examples.
8. **Bundling & registration** — `package.json` `pragma.pluginId`/`pragma.main`, bunup build to `dist/pragma-plugin.mjs`, dev registration via `.pragma/config.json` `plugins[]`, host-tool install via the host's own mechanism (one line each).
9. **Verify loop (mandatory close)** — `pragma-cli agent verify --agent <id> --abort-input '\x1b'`; fix and re-run until every scenario passes; never hand off with failures. Plus `bun run check` and package Vitest tests.
10. **Checklist** — statuses empirically verified, env guard, cleared-on-load/exit, id parity, usage-limit provider when applicable, verify all green, AGENTS.md updated.

## B — `pragma-cli agent verify`

Drives the whole run through the **gateway HTTP API** — catalog, launch (`POST /v1/control/agentSessionLaunch`, falls back to `launch_agent_headless` when no desktop is connected), NDJSON event stream, decision/answer posts, PTY input for abort bytes, session kill. Exercising the gateway _is_ the mobile-compat test.

### CLI surface

```rust
// crates/pragma-cli/src/cli.rs — new AgentCommand variant
Verify(AgentVerifyArgs),

pub struct AgentVerifyArgs {
    #[arg(long)] pub agent: String,               // agent id from the catalog
    /// Abort emulation bytes, escapes supported: \e \x1b \r \n \t \xNN
    #[arg(long = "abort-input", default_value = "\\x1b")]
    pub abort_input: String,
    #[arg(long)] pub worktree: Option<String>,    // default $PRAGMA_WORKTREE_ID
    #[arg(long)] pub model: Option<String>,       // default: first catalog model
    #[arg(long = "scenario")] pub scenarios: Vec<String>, // filter, repeatable
    #[arg(long)] pub fail_fast: bool,             // default: run all, report all
    #[arg(long, default_value_t = 2)] pub attempts: u32,  // LLM nondeterminism
    #[arg(long, default_value_t = 120)] pub step_timeout: u64,
    #[arg(long)] pub include_slow: bool,          // decision-timeout scenario
    #[arg(long)] pub prompts: Option<String>,     // JSON prompt overrides
}
```

Output rides the existing global `--json` / `--toon` flags (`crates/pragma-cli/src/output.rs`); plain text renders via `Output::list`. Exit non-zero when any scenario fails (skips don't fail).

### Design decisions

- **Session per scenario.** Each scenario launches fresh with its crafted prompt as the launch prefill — failure isolation, no mid-turn prompt delivery problems. Teardown kills the PTY and waits for settle.
- **Prompt templates live in the CLI**, overridable via `--prompts file.json` keyed by scenario id. Not a `defineAgent.verify` field: `CatalogAgent` doesn't carry it and the schema/typify churn isn't worth it now; can layer in later without breaking anything.
- **Continue-on-failure default** (`--fail-fast` opt-in): full report is what plugin authors need.
- **Requirement mapping — "interrupt" kind:** `AgentAttentionKind` is only `question | command` in `schema.json`. Interrupt coverage maps to the existing `AgentInterrupt` fan-out event (`POST /v1/agents/interrupts` → watcher sends ESC). No schema change.

### Files touched

Create: the seven `agent_verify/` modules above.

Modify:

- `crates/pragma-cli/src/cli.rs` — Verify variant + parse tests
- `crates/pragma-cli/src/main.rs` — dispatch
- `crates/pragma-cli/Cargo.toml` — add `pragma-client`, `reqwest` (blocking; already pinned in the lockfile via gateway — hoist to workspace deps)
- `packages/plugins-host/src/cli.ts` + new `usage-limits.ts` — `{'{action:"usageLimits", pluginId}'}` invoking each `usageLimits[].load(ctx)`, reusing the `PluginContext` plumbing async `models` already uses
- `crates/pragma-server/src/plugins_host.rs:188` — allow `usageLimits` passthrough

### Testing story

- `events.rs`: synthetic NDJSON via `impl Read` — parse all variants, strict rejection → `schema_errors`, wait/timeout/cursor semantics.
- `engine.rs`: `TestFeeder` injects delayed events from another thread.
- `prompts.rs`: escape parsing (`\x1b`, `\e`, bad hex → error).
- `report.rs`: JSON snapshot + TOON round-trip, mirroring `output.rs` tests.
- Scenario logic: `ScriptedAgent` fake behind `trait VerifyApi` replays scripted event sequences — every scenario's happy + failure path runs in `cargo test` with no LLM, no server.
- Full-stack run stays manual: `pragma-cli agent verify --agent opencode` against a dev server.

## Risks & open items

<Accordion type="multiple">

<AccordionItem value="llm">

<AccordionTrigger>LLM prompt obedience (main flakiness source)</AccordionTrigger>

<AccordionContent>

Real agents may answer without using the question tool, refuse, or vary. Mitigations: per-scenario retries with fresh sessions (`--attempts`, default 2), tuned templates ending with explicit stop instructions, `--prompts` overrides for per-agent tuning, `UnexpectedAgentBehavior` classified as retryable. "100% certainty" reads as: every scenario must pass, but a scenario passes on any successful attempt.

</AccordionContent>

</AccordionItem>

<AccordionItem value="interrupt-kind">

<AccordionTrigger>"Interrupt" attention kind — schema decision</AccordionTrigger>

<AccordionContent>

`AgentAttentionKind` in `packages/constants/schema.json` is `question | command` only. Plan covers interrupt via the existing `AgentInterrupt` fan-out event. If you want a literal third attention kind, that's a schema + typify + SDK + plugins change — out of scope here unless you say otherwise.

</AccordionContent>

</AccordionItem>

<AccordionItem value="workspace">

<AccordionTrigger>Workspace snapshot precondition</AccordionTrigger>

<AccordionContent>

Headless launch needs a published workspace snapshot to resolve `projectId` for the target worktree. Verify surfaces this as a clear config error ("open the project in Pragma once, or pass ids explicitly"), never as a scenario failure.

</AccordionContent>

</AccordionItem>

<AccordionItem value="prefill">

<AccordionTrigger>Prefill delivery race</AccordionTrigger>

<AccordionContent>

Launch prompt delivery is a fixed-delay PTY write (`schedule_agent_launch`); a slow agent binary can miss it. The "no `running` within timeout" failure names this mode explicitly in the evidence so authors tune `prefillDelayMs` rather than chase ghosts.

</AccordionContent>

</AccordionItem>

<AccordionItem value="watcher">

<AccordionTrigger>Interrupt scenario needs a live watcher</AccordionTrigger>

<AccordionContent>

Headless launches start plugin watchers best-effort. When no watcher is declared, interrupt fan-out lands nowhere; verify distinguishes via "no settle after interrupt, but settle after direct abort bytes" and reports skipped-with-reason.

</AccordionContent>

</AccordionItem>

</Accordion>
