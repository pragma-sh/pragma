# Terminal workspace

Turn the Pragma scaffold into a terminal workspace for juggling shells across multiple
projects and **nested git worktrees**. Three panes: a worktree sidebar with a project
switcher, a top tab strip, and an xterm.js terminal. Business logic (PTY, git, SQLite,
favicons) lives in Rust; the frontend is React + shadcn/ui + `motion/react`.

### Sidebar

- **Top row:** the project name. It _is_ the main checkout — modeled as a `worktrees` row with `isMain = 1` — so clicking it selects the main branch and the tree stays uniform.
- **Tree:** worktrees nest via `parentId` (SQLite, not git). Children render indented inside their parent. Hover reveals two affordances per row: a collapse chevron (shadcn `Collapsible`, only when the row has children) and a **+** that opens the create-worktree dialog pre-based on that row.
- **Footer — project switcher:** one icon per project, ordered by `orderIndex`. Icon = project favicon (served from Rust as base64); fallback = the project's 1-based order number. shadcn `Tooltip` shows the name on hover; click switches. A trailing dashed **+** opens the create-project dialog.
- **Swipe:** a `wheel` listener on the sidebar accumulates horizontal `deltaX` with a threshold + ~300ms cooldown → previous/next project. Works for trackpads on both macOS and Linux.
- **Animation:** `motion/react` — `AnimatePresence` slides the worktree tree out/in on project switch (quick, ~150ms, direction matches swipe), and a `layoutId` indicator glides between switcher icons.

### Top tabs

shadcn `Tabs` as the strip chrome, state owned by the workspace reducer. Placeholder titles ("Terminal 1", "Terminal 2", …), an **×** per tab, a trailing **+** that opens a new tab whose cwd is the **selected worktree's path**. Tab content hosts one terminal each; inactive terminals are hidden with CSS, never unmounted, so sessions and scrollback survive switching.

### Keyboard shortcuts

| Chord                                     | Action                         |
| ----------------------------------------- | ------------------------------ |
| `Ctrl` (macOS) / `Alt` (Linux) + `1`–`9`  | Jump to project by order index |
| modifier + `Tab` / modifier + `Shift+Tab` | Cycle tabs forward / back      |

One window-level `keydown` hook (`use-shortcuts.ts`); `navigator.platform` picks the modifier. **Gotcha:** xterm swallows keystrokes when focused, so every terminal installs `attachCustomKeyEventHandler` returning `false` for these chords so they bubble up.

### State

React context + `useReducer` — no new state dep. The only high-frequency stream
(terminal output) bypasses React entirely via `terminal-manager.ts`, so the reducer
only handles low-frequency workspace shape. Tabs are **persisted** (a `tabs` row per
open terminal): because the daemon keeps shells alive across app restarts, on launch
the reducer rehydrates tabs and each `TerminalView` **reattaches** to its existing
daemon session — replayed scrollback included — instead of spawning a fresh shell.

### The daemon (`crates/pragma-daemon/src/`)

A standalone binary crate in the Cargo workspace, **not** a Tauri sidecar (sidecars die
with the app — that would defeat the point). The app launches it detached (`setsid`, new
session, stdio to a log file) so it outlives every window. It is idempotent: a second
launch sees the socket already bound and exits.

| File          | Responsibility                                                                                                                                                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `main.rs`     | Bind the Unix socket (single-instance via flock on a lockfile), accept loop, graceful idle shutdown when the last session exits **and** no client is attached                                                                                      |
| `session.rs`  | `Session { pty, child, writer, scrollback: RingBuffer, subscribers }`; spawns `$SHELL -l`, owns the PTY master + reader thread with UTF-8 carry-over, appends to a bounded scrollback ring (e.g. last 256 KB), fans output out to attached clients |
| `protocol.rs` | The wire protocol — `Request` / `Response` tagged enums, length-prefixed JSON framing. **Shared with the app via `@pragma/constants`** so both ends use one contract                                                                               |
| `registry.rs` | `Mutex<HashMap<sessionId, Session>>`; `attach` replays scrollback then streams live frames; `spawn` / `write` / `resize` / `kill`                                                                                                                  |

**Socket path:** `$XDG_RUNTIME_DIR/pragma/daemon.sock` on Linux, falling back to
`app_data_dir/daemon.sock` (used directly on macOS, which has no `XDG_RUNTIME_DIR`).

### Key decisions

- **Background daemon, not in-process PTYs** — the whole point is that shells survive the window closing, so PTYs live in a separate detached `pragma-daemon` process the app attaches to over a Unix socket (the tmux model). A Tauri sidecar won't do — sidecars are killed with the app. The app **launches the daemon detached** (`setsid` + new session, stdio redirected to a log) on first connect, then talks length-prefixed JSON frames. On window close the app just drops the socket; the daemon and every shell keep running. On relaunch the app reads persisted `tabs` and `pty_attach`es each one, getting replayed scrollback first. The daemon idle-exits once its last session ends and no client is attached, so it never leaks forever.
- **`portable-pty`** — wezterm-extracted, no tokio coupling, and its internal `unsafe` lives outside our `unsafe_code = "forbid"` workspace. Runs **inside the daemon**, never the app. Shell = `$SHELL` (fallback `/bin/zsh` on macOS, `/bin/sh` on Linux) launched with `-l` so the user's profile/rc files load; env gets `TERM=xterm-256color`, `COLORTERM=truecolor`.
- **Tauri `Channel<PtyEvent>`, not events** — per-session, ordered, no global event-name namespacing, no extra capability permissions. `PtyEvent` is a small hand-written tagged enum on both sides (the one documented exception to schema-generated types — typify's tagged-union output is brittle for a 2-variant streaming protocol):

```rust
#[derive(Clone, serde::Serialize)]
#[serde(tag = "type", rename_all = "camelCase")]
pub enum PtyEvent {
    Output { data: String },
    Exit { code: Option<i32> },
}
```

- **git CLI over `git2`** — clone reuses the user's ssh-agent / credential helpers for free, worktree support is complete, and compile times stay sane. `create_worktree` runs `git -C <parent_path> worktree add -b <branch> <path>` so the base commit is the **parent worktree's HEAD**. `.pragma/` is appended idempotently to `.git/info/exclude` (shared across all worktrees, never dirties the repo).
- **Favicon probe** — ordered dirs `["", "public", "static", "assets", "src", "src/assets", "app"]` × names `["favicon.svg", "favicon.ico", "favicon.png", "icon.svg", "icon.png"]`, first hit returns `{ mime, dataBase64 }`; frontend caches per project for the app run.
- **Capabilities** — add `"dialog:default"` to `capabilities/default.json`; channels are covered by `core:default`.

### SQLite schema (`app_data_dir/pragma.db`, rusqlite bundled)

```sql
CREATE TABLE projects (
  id          TEXT PRIMARY KEY,              -- uuid v4
  name        TEXT NOT NULL,
  path        TEXT NOT NULL UNIQUE,          -- absolute root checkout path
  order_index INTEGER NOT NULL,              -- switcher order, number badge, shortcut digit
  created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE worktrees (
  id         TEXT PRIMARY KEY,               -- uuid v4 = dir name under .pragma/worktrees/
  project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  parent_id  TEXT REFERENCES worktrees(id) ON DELETE CASCADE,  -- NULL for main
  branch     TEXT NOT NULL,
  title      TEXT,                           -- optional display title
  path       TEXT NOT NULL UNIQUE,
  is_main    INTEGER NOT NULL DEFAULT 0,     -- 1 = project root checkout
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_worktrees_project ON worktrees(project_id);

CREATE TABLE settings (
  key   TEXT PRIMARY KEY,                    -- 'projectsDirectory'
  value TEXT NOT NULL
);

CREATE TABLE tabs (
  id           TEXT PRIMARY KEY,             -- uuid v4 = daemon sessionId
  project_id   TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  worktree_id  TEXT NOT NULL REFERENCES worktrees(id) ON DELETE CASCADE,
  title        TEXT,                         -- optional display title
  order_index  INTEGER NOT NULL,             -- position in the tab strip
  created_at   TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_tabs_project ON tabs(project_id);
```

**Modeling note:** the project's root checkout is itself a `worktrees` row
(`is_main = 1`, `parent_id = NULL`). The sidebar tree is uniform — the project-name
header row _is_ the main worktree. Nesting lives entirely in `parent_id`, which is
exactly the part git can't express.

**Tabs are persisted now** (they weren't in the ephemeral design) because the daemon
keeps each shell alive across restarts. A `tabs` row's `id` _is_ the daemon `sessionId`,
so on launch the app reattaches each tab to its still-running session. A row is deleted
when the user closes the tab (which `pty_kill`s the session) or when the daemon reports
that session already `Exit`ed while the app was away.

### Shared types (`packages/constants`)

`Project`, `Worktree`, `Tab`, and `ProjectIcon` are added to `schema.json` as
**unreferenced definitions** — both generators (`json-schema-to-typescript` and typify)
emit types for all definitions, so we get one cross-language contract with **no
`values.json` change** and no new tooling. Keep these definitions constraint-free (no
`minimum`/`format`) to avoid typify surprises like `NonZeroU64`. Re-export from
`src/index.ts` and `src/lib.rs`.

The **daemon wire protocol** (`Request` / `Response` enums) is shared the same way, so
the app's `DaemonClient` and the daemon's `protocol.rs` are generated from one schema —
no hand-kept duplicate of the frame shapes across the socket. The streaming `PtyEvent`
tagged enum stays the one documented hand-written exception (see Rust → Key decisions).

## Details worth reading before implementing

<Accordion type="multiple" className="my-4">
  <AccordionItem value="risks">
    <AccordionTrigger>Risks & gotchas</AccordionTrigger>
    <AccordionContent className="space-y-2 text-sm">

- **UTF-8 chunk splitting** — the daemon's PTY reader must carry incomplete trailing bytes between 8KB reads (`from_utf8` + `valid_up_to()`); `from_utf8_lossy` is a latent mojibake bug for multibyte output. The scrollback ring stores raw bytes, so split a multibyte char only at the carry boundary, never at the ring's truncation edge.
- **Don't kill PTYs on app exit (it's now the bug, not the fix)** — the daemon owns the shells precisely so they outlive the window. On `RunEvent::Exit` the app only closes its socket; the daemon must keep running. Inverting the old "kill all on exit" rule is the whole feature — make sure nothing (sidecar semantics, child-process groups) drags the daemon down with the app.
- **Reader thread shutdown (daemon side)** — blocking `read()` only unblocks when the PTY master drops. `kill` (from a closed tab) must kill the child **and** drop master + writer; never join first. This lives in the daemon, isolated from the app lifecycle.
- **Daemon single-instance & races** — two windows (or a fast relaunch) can both try to spawn the daemon. Guard the socket with an flock'd lockfile; the loser connects to the winner's socket. A stale socket file after a crash must be detected (connect-fails → unlink → rebind) so launch doesn't wedge.
- **Reattach resize** — a reattached tab's xterm may differ in size from when it detached; send a `pty_resize` immediately after `pty_attach` so the daemon SIGWINCHes the shell to the current geometry before/after replaying scrollback.
- **Hidden-tab resize** — xterm can't measure `display:none` containers; call FitAddon on tab activation, and debounce resize (~75ms) so TUIs don't flicker under SIGWINCH storms.
- **xterm steals shortcuts** — without `attachCustomKeyEventHandler` returning `false` for our chords, tab cycling dies whenever a terminal is focused.
- **xterm CSS** — `@xterm/xterm/css/xterm.css` must be imported or the terminal renders broken. Skip the WebGL addon: unreliable on WebKitGTK (Linux).
- **git worktree locking** — serialize mutating git ops per project; `worktree add -b` fails if the branch already exists or is checked out elsewhere — surface stderr verbatim in the dialog.
- **Output flooding** — `cat bigfile` spams the channel; xterm buffers writes so 8KB reads are usually fine, but never route output through React state.
- **rusqlite is `!Sync`** — `Mutex<Connection>` in managed state.
- **clippy pedantic** — budget for `u16`→`usize` cast lints in PTY sizing; justify any `#[allow]`.

</AccordionContent>

  <AccordionItem value="alternatives">
    <AccordionTrigger>Alternatives considered</AccordionTrigger>
    <AccordionContent className="space-y-2 text-sm">

- **`tauri-plugin-sql`** — rejected: pushes SQL strings into the frontend; the requirement keeps business logic in Rust, and rusqlite is directly `cargo test`-able.
- **`git2` crate** — rejected: partial worktree support, heavy compile, and clone needs manual credential-callback plumbing the CLI gets free from the user's config.
- **Tauri events for PTY output** — rejected: global broadcast requires per-session event-name namespacing and extra capability surface; `Channel` is ordered and scoped.
- **zustand** — rejected: with terminal output bypassing React, remaining state is low-frequency; context + reducer carries it without a new dependency.
- **Ephemeral (non-persisted) tabs** — rejected once the daemon exists: a reattached tab is the _same live shell_ with replayed scrollback, not a fresh one, so persisting tabs is what makes the background daemon visible to the user. Hence the `tabs` table.
- **In-process PTYs + kill-on-exit** — the original design; rejected because shells must survive window close. Replaced by the detached daemon (see Rust → Key decisions).
- **Tauri sidecar for the daemon** — rejected: Tauri terminates sidecars when the app exits, which is exactly what we need to avoid. The daemon is launched fully detached (`setsid`) instead.
