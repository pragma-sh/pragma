# Prompt Kanban Workspace

Add a **project-scoped prompt board** that replaces the sidebar new-chat entry point
with a Kanban icon. Clicking it leaves the normal terminal workspace mounted in app
state, but visually replaces the full app shell with a board for writing, saving, and
starting prompts. The existing `NewAgentSessionDialog` stays available for deeplinks and
other entry points.

<Card className="my-4">
  <CardHeader>
    <CardTitle>At a glance</CardTitle>
    <CardDescription>What ships and where the risk is</CardDescription>
  </CardHeader>
  <CardContent className="space-y-2 text-sm">

- **New full-app mode:** `WorkspaceShell` toggles between normal workspace UI and `ProjectKanbanWorkspace`.
- **Entry point change:** `ProjectSidebar` replaces the `MessageSquarePlus` button with a Kanban icon button.
- **Deeplink safety:** move the `NewAgentSessionDialog` event host out of `ProjectSidebar` so `pragma://open` still works while the board is visible.
- **Persistent cards:** add SQLite-backed kanban prompt records, scoped to the selected project.
- **Board columns:** Drafts, In progress, Review needed, Completed.
- **Hardest technical part:** background agent launch. Starting a card must create a tab and spawn the PTY without requiring `TerminalView` to mount.
- **Future scheduling:** persist manual queue fields now so timed scheduling can be added later without reshaping cards.

</CardContent>
</Card>

## User Flows

<Accordion type="single" collapsible className="my-4">
  <AccordionItem value="drafts">
    <AccordionTrigger>Draft creation and editing</AccordionTrigger>
    <AccordionContent>

`DraftPromptDialog` should look like `CreateWorktreeDialog`, with one important change:
the branch input is a combobox over existing project worktrees. If the typed value does
not match a worktree branch, show a "Create new worktree" option and save it as a pending
branch.

Fields:

- Branch or existing worktree.
- Prompt textarea.
- Agent selector using the same `listAgents` data as new sessions.
- Model selector if the selected agent exposes models.

Buttons:

- Save persists or updates a draft card.
- Discard draft deletes an existing draft after confirmation.
- Discarding an unsaved, dirty modal should confirm before closing.

Clicking a Drafts card opens the same dialog prefilled for editing.

</AccordionContent>
  </AccordionItem>

  <AccordionItem value="progress">
    <AccordionTrigger>In progress behavior</AccordionTrigger>
    <AccordionContent>

In progress cards are not user-draggable. They reflect the spawned agent session.

- Footer shows the selected agent and model.
- If `useTabAgentStatus(agentTabId)` or `useWorktreeAgentStatus(worktreeId)` reports attention, show an attention badge.
- Current reports only have `attentionKind`; if the product requires exact question or command text, extend `AgentReportPayload` with optional `attentionMessage` or `attentionCommand` in `packages/constants`.
- Clicking the card opens the worktree in normal workspace and shows **Back to Kanban**.
- A `done` report for the matching `agentTabId` moves the card to Review needed.

</AccordionContent>
  </AccordionItem>

  <AccordionItem value="review">
    <AccordionTrigger>Review and completion</AccordionTrigger>
    <AccordionContent>

Review cards open their worktree when clicked. Dragging to Completed opens
`CompleteReviewDialog` and defers the status change until the chosen action completes.

- Commit all and merge performs the AI commit message, commit, local merge, then cleanup prompt.
- Commit all and open PR launches the same submit PR screen as the GitHub integration and records PR metadata after creation.
- Go to worktree marks the card complete, navigates to the worktree, and lets the user finish manually.

Completed cards are read-only for MVP. If a completed card has PR metadata, show a PR-open
badge on the card.

</AccordionContent>
  </AccordionItem>

  <AccordionItem value="navigation">
    <AccordionTrigger>Back behavior</AccordionTrigger>
    <AccordionContent>

Use two distinct back paths:

- Board Back button: exits Kanban mode to the normal workspace and does not show a return pill.
- Card-driven navigation: exits to normal workspace and sets `returnToKanbanProjectId`, causing a visible **Back to Kanban** button in the normal workspace chrome.
- Back to Kanban: reopens the same project board and clears the return state.

This keeps intentional escape from the board separate from temporary review navigation.

</AccordionContent>
  </AccordionItem>
</Accordion>
