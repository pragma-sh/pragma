# Agent Connector

Let **external agents report status into Pragma**, and let **Pragma spawn agents from the
UI**. An agent running inside a Pragma terminal calls a new `pragma-agent` CLI to report
`started` / `stopped` / `attention`; the report rides the **existing `pragma-daemon`
socket**, the app fans it out to React, and the UI lights up per-tab and per-worktree
status dots, plays a chime, raises a sonner (or a system notification when unfocused),
and offers cross-project "go to / go back" navigation. The agents dropdown spawns an
agent into a **new terminal tab** by running its configured `start` command.

<Card className="my-4">
  <CardHeader>
    <CardTitle>At a glance</CardTitle>
    <CardDescription>What ships and what it costs</CardDescription>
  </CardHeader>
  <CardContent className="text-sm space-y-2">

- **2 new Rust crates:** `pragma-protocol` (extract the wire protocol from the daemon, **remove the `pty.rs` hand-mirror**) and `pragma-agent-cli` (the `pragma-agent` binary, shipped as a Tauri sidecar)
- **Daemon wire change:** new `AgentReport` + `SubscribeAgents` request frames, an `EventFrame::Agent` broadcast, a registry status map with a snapshot-on-subscribe, and `PRAGMA_*` env injection in `Session::spawn` — **bump `daemon.protocolVersion` 3 → 4**
- **Shared constants:** `AgentStatus`, `AgentReportKind`, `AgentReportPayload` in `packages/constants`
- **App backend:** an agent-subscription bridge emitting a `pragma:agent-report` event, a CLI installer (`agent_cli.rs`), and an agent-config loader (`agents.rs` + `list_agents`) reading `~/.pragma/agents/<name>/config.json`
- **Frontend:** an ephemeral `agent-status-store`, status dots in the sidebar + tabs, chime + sonner + system notification, cross-project `navigateToAgentLocation`, a 10-minute "Go back" top-bar button, and an agents dropdown with pinning
- **Tooling:** a mock agent under `tools/mock-agent` + a `~/.pragma/agents/mock` config for manual end-to-end testing
- **No SQLite migration** — agent status is runtime-only; pin state is `localStorage`

</CardContent>
</Card>

the worktree dot is the **priority aggregate** of its tabs. Change the two tab states and

**`pragma-agent`** — agent-facing surface. `--agent <id>` is required and global;
`PRAGMA_TAB_ID` / `PRAGMA_WORKTREE_ID` come from env (no flags).

```text
pragma-agent --agent <id> report started
pragma-agent --agent <id> report stopped [--worktree-id <id>]
pragma-agent --agent <id> report attention [--kind question|command]
```

- `stopped --worktree-id` **overrides** `PRAGMA_WORKTREE_ID` so a user can mark a worktree's agent done from outside that worktree's shell (manual abort). Defaults to the env var.
- Behavior: read `PRAGMA_DAEMON_SOCKET` → connect → read `Hello` → write one `AgentReport` frame → exit 0. Connect failure exits non-zero with a short stderr line but never blocks the agent. **Never waits for a response.**

**Agent config** — global config root is `~/.pragma` (same root as `keybindings.json`).
Each agent: `~/.pragma/agents/<agent-name>/config.json` + an icon file beside it.

## End-to-end flows

<Accordion type="single" collapsible className="my-4">
  <AccordionItem value="report">
    <AccordionTrigger>An agent reports attention</AccordionTrigger>
    <AccordionContent>

1. Agent in a tab shell runs `pragma-agent --agent claude report attention --kind question`.
2. CLI reads `PRAGMA_TAB_ID` / `PRAGMA_WORKTREE_ID` / `PRAGMA_DAEMON_SOCKET`, connects, reads `Hello`, writes one `AgentReport` frame, exits.
3. Daemon updates its status map and fans out `EventFrame::Agent` to every subscriber.
4. The app's subscription bridge receives it and emits `pragma:agent-report`.
5. `agent-status-store` updates `(worktree, tab, agent) → attention`; the tab dot goes red-blink, the worktree dot aggregates to attention.
6. The transition fires `lib/agent-alert`: chime + (focused) a sonner "Claude has a question" with **Go to worktree →**, or (unfocused) the same as a system notification.

</AccordionContent>
  </AccordionItem>
  <AccordionItem value="navigate">
    <AccordionTrigger>Go to worktree, then go back (cross-project)</AccordionTrigger>
    <AccordionContent>

1. Click **Go to worktree** (sonner) or the system notification → focus window + `navigateToAgentLocation(projectId, worktreeId, tabId)`.
2. If `projectId` differs from the loaded project, switch project first (existing `reload`/per-project active-worktree restore), then select the worktree, then activate the tab (handling split members).
3. The navigation records the **previous** `{ projectId, worktreeId, tabId }` + a timestamp.
4. A **Go back to &lt;worktree&gt;** button appears in the top bar next to the editor launcher; it navigates back and **persists for 10 minutes**, then hides.

</AccordionContent>
  </AccordionItem>
  <AccordionItem value="launch">
    <AccordionTrigger>Launch an agent from the dropdown</AccordionTrigger>
    <AccordionContent>

1. `list_agents` populates the menu (icons as data URLs). Pinned agents show as chips left of the trigger; the row overflows with horizontal scroll.
2. Click an agent → `createTerminalTab(activeWorktreeId)` → a new tab spawns with `PRAGMA_TAB_ID`/`PRAGMA_WORKTREE_ID` set.
3. Resolve `start` (string as-is; array joined for the shell) and `ptyWrite(newTabId, command + "\n")` once the session is up.
4. The agent's own `pragma-agent report` calls then light up that tab's dot.

</AccordionContent>
  </AccordionItem>
</Accordion>

## Risks & edge cases

<Card className="my-4">
  <CardContent className="text-sm space-y-2 pt-6">

- **`pty.rs` mirror removal** is the riskiest edit — gate behind a green step 1, or defer and keep the mirror while the CLI/daemon still share `pragma-protocol`.
- **`~/.local/bin` not on `$PATH`** on some Linux setups — the installer must detect and advise, never silently fail.
- **System notifications** need the notification plugin + capability + OS permission; first run may prompt. Click-to-navigate plumbing differs slightly mac vs Linux.
- **App restart mid-session** — the snapshot on `SubscribeAgents` rehydrates dots for shells the daemon still knows; without it statuses are lost until the next report.
- **Multiple agents per tab** — the model supports it (per-tab aggregate), but confirm the common one-agent-per-tab case stays visually unambiguous.
- **Headless webview can't paint xterm/UI** (per project memory) — automated coverage lives in the daemon socket + store logic; the mock agent carries the visual/audio/notification confirmation.
- **Chime asset licensing** — pick a freely-licensed or self-made sound.

</CardContent>
</Card>

## Build order

<Card className="my-4">
  <CardContent className="text-sm space-y-2 pt-6">

1. **`pragma-protocol` crate** — extract framing; wire `pragma-daemon` + `src-tauri` to it (remove the `pty.rs` mirror). Green build + existing tests first.

6. **Frontend state** — `agent-status-store` + `onAgentReport` listener + transition detection.
7. **Frontend UI** — status dots (sidebar + tabs), agents dropdown + pinning, chime, sonner, system notification, go-to / go-back navigation.
8. **Mock agent** + `~/.pragma/agents/mock`; full manual pass.
9. **Quality gates** — `bun run check` (`code-quality` skill) + update `CLAUDE.md` and the relevant `.agents/skills/*` for the new daemon frames, env vars, CLI install, and agent config.
